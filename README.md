# YH Lab (Protein Design Lab) GitHub Organization

Sungkyunkwan University(SKKU) Yongho Kim 교수님 연구실(Protein Design Lab)의 공식 GitHub Organization입니다.
연구실 내에서 개발한 코드/파이프라인을 랩원들이 함께 사용하고, 코드 협업을 진행하는 공간입니다.

---

## 이 Organization을 사용하는 목적

- 랩원 개인이 개발한 코드를 랩 전체가 재사용할 수 있도록 공유
- 여러 명이 함께 개발/유지보수하는 파이프라인의 협업 공간
- 랩 내 코드 자산의 일관된 관리 (버전 관리, 문서화, 재현성 확보)

---

## 시작하기 전에 (신규 멤버)

1. Organization에 초대되면 수락 후, 본인이 참여할 프로젝트의 레포에 접근 권한이 있는지 확인하세요.
2. 새 레포를 만들거나 기존 레포에 기여하기 전에 아래 **사용 규칙**을 반드시 읽어주세요.
3. 레포별 상세 사용법은 각 레포의 `README.md` / `CONTRIBUTING.md`를 참고하세요. (이 문서는 랩 전체 공통 규칙만 다룹니다.)

---

## 레포지토리 규칙

### 이름 규칙
`프로젝트명-목적` 형식을 권장합니다.
예: `artemis-vdm-motif-design`, `ysd-h5n1-pipeline`

### 필수 포함 항목
새 레포를 만들 때 아래 항목을 최대한 포함해주세요.

- `README.md`: 프로젝트 목적, 사용법, 예시 실행 명령어
- 의존성 명세 파일: `environment.yml` 또는 `requirements.txt` (재현성 확보를 위해 필수)
- `.gitignore`: 대용량 파일(모델 가중치, raw 데이터, 로그 등)이 실수로 커밋되지 않도록 설정

### 공개 범위
기본적으로 **Private**로 생성합니다. 논문 공개, 오픈소스 배포 등 명확한 사유가 있을 때만 Public 전환을 논의합니다.

## 코드 협업 규칙

> ⚠️ 현재 Organization은 GitHub Free 플랜이며, Private 레포에서는 branch protection(ruleset)이 기술적으로 강제되지 않습니다.
> 즉, 아래 규칙은 **자동으로 막히지 않으니 모두 자율적으로 지켜야** 합니다.

### 브랜치 전략
- `main` 브랜치는 항상 동작 가능한 상태로 유지합니다. **직접 push하지 않습니다.**
- 새로운 작업은 브랜치를 따서 진행합니다.
  - 기능 개발: `feature/작업내용`
  - 버그 수정: `fix/버그내용`
  - 실험/분석: `exp/실험내용`

### Pull Request
- 작업이 끝나면 `main`으로 PR을 올립니다.
- 가능하면 리뷰어를 1명 이상 지정해주세요. (랩 인원이 적어 항상 가능하지는 않을 수 있습니다 — 여의치 않으면 최소한 PR 설명에 변경 사항을 명확히 남겨주세요.)
- PR 설명에는 다음을 포함해주세요.
  - 무엇을, 왜 변경했는지
  - 테스트/검증 방법 (있다면)

### 커밋 메시지
아래 prefix를 권장합니다 (강제 아님, 검색/이력 관리 편의를 위한 권장 사항).

| Prefix | 의미 |
|---|---|
| `feat:` | 새 기능 추가 |
| `fix:` | 버그 수정 |
| `docs:` | 문서 수정 |
| `refactor:` | 리팩터링 (기능 변화 없음) |
| `data:` | 데이터/실험 결과 관련 |
| `chore:` | 기타 잡일 (설정, 의존성 등) |
